# Commit Examples Guide

This document provides practical examples of Conventional Commit messages based on common scenarios.

---

## Initial Setup

```
docs: add initial project structure and documentation
```

---

## Folder Structure or Configuration Changes

```
chore: create base project structure
```

```
chore: update .gitignore for multiple stacks
```

---

## Documentation Updates

```
docs: add usage and branch strategy guides
```

```
docs(readme): update instructions for new projects
```

---

## Scripts or Utilities

```
chore(scripts): add create-branch.sh
```

```
fix(scripts): correct branch creation logic
```

---

## New Feature Development

```
feat(auth): add login with Google
```

```
feat(products): add search filter by name
```

---

## Bug Fixes

```
fix(products): prevent crash when product name is null
```

```
fix(api): correct response status code on error
```

---

## Refactoring

```
refactor(user-service): clean unused methods
```

```
refactor(controllers): improve error handling
```

---

## Testing

```
test(api): add tests for order controller
```

```
test(products): update product model tests
```

---

## CI/CD Configuration

```
ci(github-actions): add deployment workflow
```

```
ci(github-actions): fix typo in workflow config
```

---

Use this guide as a reference to keep commit messages consistent, clear, and easy to understand.
